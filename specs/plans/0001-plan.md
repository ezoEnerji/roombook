## Ordered steps

1. **Skeleton green.** Solution, `Directory.Build.props`, `.editorconfig`, `.gitattributes`, the three
   `src` projects and the three test projects with their references; activate the three steps in
   `scripts/check.conf`. Ends with `./scripts/check` green on an empty solution — AC-1 before any
   behavior exists, so every later step is verified as it lands.
2. **Architecture rules.** FD-1…FD-6 as pure inspection rules plus the tests that prove each rule fails
   on a violating input. Second on purpose: the boundaries are guarded before there is code to guard.
3. **Domain.** `Error`, `Result`, `BusinessHours`, `Room` with its validating factory, and the domain
   tests for AC-6, AC-7, AC-8.
4. **Application.** `IRoomRepository` and `ListRoomsUseCase` with ordinal name ordering.
5. **API.** Composition root and JSON options, the in-memory repository, the seed data, `GET /rooms`
   and its DTO.
6. **Contract tests.** `WebApplicationFactory` tests for AC-3, AC-4, AC-5 and AC-9, including a host
   built with an empty repository to prove AC-5 (which also proves seeding is a composition-root
   concern, not something baked into the adapter).
7. **Documentation clauses** and the spec/plan status updates.

## Risks & open questions

- **Line endings will break `dotnet format` in CI.** The repository is authored on Windows and verified
  on `ubuntu-latest`. *Recommendation:* add `.gitattributes` with `* text=auto eol=lf` and
  `end_of_line = lf` in `.editorconfig` in step 1, before any C# file exists. Cheap now, painful later.
- **FD-3 (no ambient clock) is the one rule with real implementation uncertainty.** A source-text scan
  is easy to fool by formatting. *Recommendation:* inspect the compiled assemblies with
  `System.Reflection.Metadata` for member references to `DateTime.get_Now/get_UtcNow` and
  `DateTimeOffset.get_Now/get_UtcNow`. No third-party package, and it sees what the compiler emitted
  rather than what the source looks like. If this turns out to be more than a small amount of code, I
  will stop and propose the alternative rather than improvise (R-07).
- **FD-1 and FD-6 read `.csproj` files, so the tests need the repository root at runtime.**
  *Recommendation:* one helper that walks upward from the test assembly until it finds `RoomBook.sln`,
  and fails loudly if it does not — a rule that silently finds no files would pass forever and prove
  nothing.
- **The architecture test project must reference all three `src` projects**, which makes it the only
  project that can see everything. *Recommendation:* the inspection rules exclude assemblies whose name
  ends in `.Tests`, and that exclusion is itself covered by a test, so it cannot quietly widen.
- **`JsonUnmappedMemberHandling.Disallow` cannot be tested in this slice** — `GET /rooms` has no request
  body. *Recommendation:* configure it now (it belongs to the composition root) but do not write an
  acceptance criterion for it; the first endpoint with a body (S-002, create booking) proves it.
- **`Microsoft.Extensions.TimeProvider.Testing` is not added yet.** Nothing in this slice reads time.
  *Recommendation:* add it in the spec that first needs it, so every dependency stays justified by a
  rule it serves (FD-6 discipline).
- **~~`TimeZoneInfo` in a domain record.~~ Resolved at the approval gate:** the IANA identifier is
  stored as a `string`, validated for resolvability at construction, and `TimeZoneInfo` is resolved
  where a calculation needs it. `Room` stays a plain value and AC-7 is still satisfied.

## Deviations recorded at build time

The plan is not rewritten to match what happened; the differences are listed here instead (R-07).

- **Added `tests/RoomBook.Architecture.Fixtures`** — an assembly that breaks FD-2…FD-5 on purpose.
  The independent review showed that feeding hand-built facts to the rules proved they *reason*
  correctly but never proved the metadata reader *sees* a real violation. Approved at triage.
- **Test names below are the planned ones**; several were renamed during build, and the Api suite
  gained a table-driven test over all three seeded rooms plus an exact JSON property-set test.
- **Not added, though planned:** the non-generic `Result` and
  `Microsoft.Extensions.TimeProvider.Testing`. Nothing in this slice returns a value-less outcome or
  reads time.
- **`ListRoomsUseCaseTests` lives in `RoomBook.Api.Tests`** — the approved layout has no Application
  test project.
- **Three things the plan did not foresee:** `.gitignore` needed .NET entries (the first commit
  attempt staged 946 files), `scripts/*` lost their executable bit when the index was rebuilt on
  Windows, and `global.json` was needed because the CI runner's .NET 10 SDK no longer supports
  xUnit v3's VSTest path.
