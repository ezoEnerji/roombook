## Ordered steps

1. **Domain interval algebra.** `TimeSlot` with `Overlaps` and duration, plus its tests. First because
   every other rule is expressed in terms of it, and because the touching case (BR-3) is the single
   most likely off-by-one in the product.
2. **Domain rules.** `Booking.Create` evaluating BR-8, BR-7, BR-4, BR-1, BR-6 in the documented order,
   `Room.IsWithinBusinessHours`, and the tests for every boundary named in the spec — including the
   daylight-saving case.
3. **Application.** The port with the atomic store operation, the two use cases, `TimeProvider`
   injected at this layer and passed inward as a value.
4. **API.** DTOs, the `ProblemDetails` mapping table, both endpoints, and the in-memory adapter whose
   lock makes BR-2 an invariant rather than a race.
5. **HTTP contract tests.** Every code and status, the precedence case, the malformed-request cases,
   and the concurrency case.
6. **ADR and documentation**, then the spec checklist.

## Risks & open questions

- **AC-14 cannot be proven with the seeded rooms.** All three are `Europe/Istanbul`, which has had no
  daylight-saving transition since 2016 — a permanent UTC+3 offset. *Recommendation:* the test builds
  its own room in `Europe/Berlin` through the existing test-host override, rather than changing seed
  data that S-001 already shipped as a client contract. Without this, AC-14 would be quietly untestable.
- **A new NuGet package needs an ADR** (`docs/security.md`). `docs/conventions.md` names
  `Microsoft.Extensions.TimeProvider.Testing` for test clocks, but we only need `GetUtcNow`, which a
  five-line `TimeProvider` subclass would also give us. *Recommendation:* honour the documented choice
  and add the package with ADR-0004 — it is first-party, test-only, and deviating from a written
  decision to save one file is the wrong trade. **Your call, and it is the only new dependency here.**
- **The precedence order must live in exactly one place.** If the API re-checks anything the domain
  already decided, the two will drift and AC-17 becomes flaky. *Recommendation:* the API validates only
  request *shape* (400 cases) and then maps codes; every business rule is evaluated once, inside
  `Booking.Create`, in the documented sequence.
- **`Location` must match the `GET` route exactly.** *Recommendation:* build it from the named route
  rather than by string concatenation, so a route rename cannot silently break the header.
- **Concurrency proof is easy to fake.** A test that sends two requests sequentially proves nothing.
  *Recommendation:* fire both with `Task.WhenAll` on the same host and assert exactly one `201` and one
  `409`; if that turns out to be flaky rather than deterministic, stop and report instead of loosening
  the assertion (R-03).
- **`Result` grows a non-generic sibling.** ADR-0003's revisit trigger mentions this. It stays hand-
  written; if it starts growing combinators, that is the moment for a library and its own ADR.

## Deviations recorded at build time

- **The non-generic `Result` was not added.** The store operation returns `Result<Booking>` — the
  booking it stored — which removes the type entirely. It also removes a naming collision: our
  convention is one type per file named after the type, and `Result` and `Result<T>` cannot both have
  it. Second slice in a row where this type turned out to be unnecessary.
- **`IRoomRepository` gained `FindAsync`**, which the plan's file list did not mention. Creating a
  booking needs one room, and `GetAllAsync` would have meant loading every room to find it.
- **`Microsoft.Extensions.TimeProvider.Testing` is only in the HTTP test project**, not in the domain
  tests as first installed. The domain receives the instant as a value, so a constant is already
  deterministic there and the dependency would have been unused (ADR-0004 records this).
- **Three domain tests had wrong data, not wrong rules.** Windows I picked as "too long" or "outside
  hours" were also in the past, so the documented precedence correctly returned `booking.start_in_past`
  and the tests failed. The fix was to the test data; the precedence order behaved exactly as designed.
